# News & Activities Content Contract

The public KHWebpage route `/news-activities` reads published rows from
`public.events`. KHBackoffice manages those rows from `/events`.

## Expected Fields

| Column | Purpose |
| --- | --- |
| `title` | Public card title. |
| `description` | Public card summary or announcement body. |
| `event_date` | Date used for sorting and display. |
| `start_date` | Optional start date shown in list and detail metadata. |
| `end_date` | Optional end date or registration deadline used for countdown labels. |
| `location` | Optional place, venue, or channel. |
| `img_src` | Public image URL written after a CMS upload. |
| `type` | Content category: `event`, `activity`, or `announcement`. |
| `status` | Public label: `upcoming`, `completed`, or `announcement`. |
| `action_label` | Optional CTA label such as `Apply Now` or `Register`. |
| `action_url` | Optional CTA URL for registration or more information. |
| `is_published` | Only `true` rows should be readable by KHWebpage. |

## SQL Setup

Run this in the Supabase SQL Editor if the `events` table has not yet been
updated for News & Activities.

```sql
create table if not exists public.events (
  id bigint generated by default as identity primary key,
  title text not null,
  description text,
  event_date date not null,
  start_date date,
  end_date date,
  location text,
  img_src text,
  type text not null default 'event',
  status text not null default 'upcoming',
  action_label text,
  action_url text,
  is_published boolean not null default false,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

alter table public.events
  add column if not exists start_date date,
  add column if not exists end_date date,
  add column if not exists action_label text,
  add column if not exists action_url text,
  add column if not exists type text not null default 'event',
  add column if not exists status text not null default 'upcoming';

alter table public.events
  drop constraint if exists events_type_check,
  add constraint events_type_check
    check (type in ('event', 'activity', 'announcement'));

alter table public.events
  drop constraint if exists events_status_check,
  add constraint events_status_check
    check (status in ('upcoming', 'completed', 'announcement'));

create index if not exists events_public_feed_idx
  on public.events (is_published, event_date desc, created_at desc);

create index if not exists events_deadline_idx
  on public.events (end_date);
```

## Row Level Security

These policies match the current CMS role model. Re-apply only after confirming
that `public.profiles.role` contains `admin` and `editor` for CMS users.

```sql
alter table public.events enable row level security;

drop policy if exists "Public can read published events" on public.events;
create policy "Public can read published events"
on public.events
for select
using (is_published = true);

drop policy if exists "Editors can manage events" on public.events;
create policy "Editors can manage events"
on public.events
for all
to authenticated
using (
  exists (
    select 1
    from public.profiles
    where profiles.id = auth.uid()
      and profiles.role in ('admin', 'editor')
  )
)
with check (
  exists (
    select 1
    from public.profiles
    where profiles.id = auth.uid()
      and profiles.role in ('admin', 'editor')
  )
);
```

## Storage Bucket

Create a public Storage bucket named `news-activities` for normal image uploads
from the CMS. Event images are uploaded under `events/{fileName}` and the public
URL is stored in `events.img_src`.

```sql
insert into storage.buckets (id, name, public)
values ('news-activities', 'news-activities', true)
on conflict (id) do update
set public = true;

drop policy if exists "Public can read news activity images" on storage.objects;
create policy "Public can read news activity images"
on storage.objects
for select
using (bucket_id = 'news-activities');

drop policy if exists "Editors can upload news activity images" on storage.objects;
create policy "Editors can upload news activity images"
on storage.objects
for insert
to authenticated
with check (
  bucket_id = 'news-activities'
  and exists (
    select 1
    from public.profiles
    where profiles.id = auth.uid()
      and profiles.role in ('admin', 'editor')
  )
);

drop policy if exists "Editors can delete news activity images" on storage.objects;
create policy "Editors can delete news activity images"
on storage.objects
for delete
to authenticated
using (
  bucket_id = 'news-activities'
  and exists (
    select 1
    from public.profiles
    where profiles.id = auth.uid()
      and profiles.role in ('admin', 'editor')
  )
);

drop policy if exists "Editors can update news activity images" on storage.objects;
create policy "Editors can update news activity images"
on storage.objects
for update
to authenticated
using (
  bucket_id = 'news-activities'
  and exists (
    select 1
    from public.profiles
    where profiles.id = auth.uid()

)

```

## Delivery Rules

- KHWebpage fetches only `is_published = true` rows.
- Backoffice can keep drafts by leaving `is_published` unchecked.
- `status` is the public label. Use `upcoming` for future items, `completed`
  for past activities, and `announcement` for general updates.
- `end_date` drives countdown labels such as `5 days left`, `Ends today`, and
  `Registration closed`.
- `action_label` and `action_url` drive the detail-page action button. When a
  deadline has passed, KHWebpage disables registration-style actions such as
  `Apply Now` or `Register` and shows `Registration closed`.
- `img_src` is set automatically after image upload. If it is empty, KHWebpage
  uses the existing camp fallback image.
